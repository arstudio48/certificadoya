1. ❌ ROW LEVEL SECURITY (RLS) BLOQUEA INSERCIONES
   ─────────────────────────────────────────────
   Error: HTTP 403 | Code: PGRST102 / 42501
   
   SÍNTOMA:
     curl POST /leads → {"code":"42501","message":"violates row-level security"}
   
   CAUSA RAÍZ:
     - Tabla `leads` tiene RLS = ON
     - Políticas RLS NO permiten INSERT anon
     - Frontend apikey pública (sb_publishable_...) tiene solo SELECT
     - INSERT requiere SERVICE_KEY o usuario autenticado
   
   IMPACTO:
     ❌ Leads NO se crean en Supabase
     ❌ Tabla siempre vacía []
     ❌ Técnicos NO ven leads
     ❌ Auto-assign no tiene qué asignar
   
   SOLUCIÓN:
     SQL: CREATE POLICY "Allow public inserts" ON leads FOR INSERT WITH CHECK (true)
     Archivo: SUPABASE-RLS-FIX.sql
     Ejecutar en: https://app.supabase.com/project/.../sql/editor


2. ❌ EDGE FUNCTION MIENTE (Retorna success=true aunque falle)
   ──────────────────────────────────────────────────────────
   Archivo: supabase/functions/solicitar-servicio/index.ts
   
   COMPORTAMIENTO:
     - INSERT falla con 42501 RLS
     - Edge Function catch el error, lo loguea
     - Retorna {"success": true} SIEMPRE
   
   CÓDIGO PROBLEMÁTICO:
     ```typescript
     if (!res.ok) {
       const errorData = await res.json()
       console.error('Error:', errorData)  // ← Solo loguea, no retorna
     }
     // Sigue aquí
     return new Response({ success: true })  // ← SIEMPRE TRUE
     ```
   
   IMPACTO:
     ❌ Cliente ve "Solicitud enviada ✅"
     ❌ Pero lead NO existe en BD
     ❌ Usuario engañado
   
   SOLUCIÓN:
     Validar res.ok y retornar error si falla
     Logging detallado en cada paso
     Commit: 52a9fc7


3. ❌ FRONTEND NO VALIDA RESPUESTA
   ──────────────────────────────
   Archivo: /reserva/index.html (solicitarSinPago function)
   
   COMPORTAMIENTO:
     ```javascript
     const res = await fetch(...)
     if (!res.ok) { mostrarError(...); return }
     // ← Nunca llega aquí porque res.ok = true siempre
     document.getElementById('reserva-success-ce').style.display = 'block'
     ```
   
   IMPACTO:
     ❌ Frontend no valida `response.success`
     ❌ No muestra `response.error` si existe
     ❌ Cree éxito aunque falle
   
   SOLUCIÓN:
     Parsear JSON
     Validar `result.success === true`
     Mostrar `result.error` si falla
     Commit: 52a9fc7


4. ❌ EDGE FUNCTION USA APIKEY PÚBLICA
   ──────────────────────────────────
   Código:
     ```typescript
     const SUPABASE_KEY = Deno.env.get('SUPABASE_SERVICE_KEY')
     // Luego...
     headers: { 'apikey': SUPABASE_KEY, ... }
     ```
   
   PROBLEMA:
     - Env var `SUPABASE_SERVICE_KEY` no está configurada
     - Si no existe, `Deno.env.get()` retorna `undefined`
     - Usa undefined como apikey (como si fuera pública)
     - RLS bloquea
   
   SOLUCIÓN:
     - Verificar que ENV var existe
     - Usar `Authorization: Bearer ${token}` NO `apikey`
     - SERVICE_KEY está disponible automáticamente en Edge Functions
     - Commit: 52a9fc7
